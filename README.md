# 田间时刻 · QQ 农场收菜时间计算器

一个在本地运行的网页，提供单次收菜时间计算和全天最优种植规划。时间输入和结果都按北京时间（UTC+08:00）解释和显示，精确到分钟。

## 本地运行

需要 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址。代码检查、计算测试和生产构建：

```bash
npm run lint
npm test
npm run build
```

## 计算规则

- 生长档位：4、8、12、24 小时。
- 第一季：播种时间 + 生长时间 × 土地系数。
- 第二季：第一次收菜时间 + 生长时间 ÷ 2 × 同一土地系数。
- 普通、黑、金土地的系数分别为 1、0.9、0.8；土地只需选择一次，两季保持一致。
- 第一次实际收菜时间留空时，第二季按第一季最早可收菜时间起算；填写后按实际收菜时间重新计算。实际时间不得早于第一季最早可收菜时间。

## 全天规划

- 选择计划日期、日循环开始时刻、一块土地、可用种子品类和至少一个睡眠时段。日循环从所选日期的开始时刻起持续 24 小时，默认 08:00 至次日 08:00；初始睡眠为 00:00–08:00，可添加午睡等时段、编辑起止时间并跨午夜设置。重叠或首尾相接的睡眠时段在计算时自动合并。种子数量不限。
- 可用种子分为普通一季、普通两季、活动一季、活动两季。活动一季预设 12 小时、经验权重 24；两个活动分组都可从分组标题旁添加自定义种子，添加后立即参与规划。自定义种子只保留在当前页面会话中。
- 从空地开始规划。今天若已过日循环起点，从当前下一分钟继续，但终点不变；若起点或当前时刻处于睡眠中，醒来后才首次播种。所有睡眠时段每天重复，睡眠期间禁止播种和收菜，之后每段从规划期间开始的完整睡眠都须由同一株作物持续占地；最早可收菜时间落在睡眠中时，收菜延至醒来。若时段合并后全天没有清醒时间，则无可行方案。
- 播种须早于循环终点。两季种子的第二季从第一次计划收菜时间起算，收完第二季才能换种。仅整份方案最后一次收菜可以晚于循环终点；两季作物的第一次收菜仍须在终点前或恰好终点完成。
- 经验权重始终最高优先。最高权重相同时，收菜次数策略可选“次数最少”“平衡”或“次数最多”，默认“次数最多”。平衡策略按最少与最多收菜次数的中点选择，等距时优先选择更早完成的方案。普通种子第一季权重为标称生长小时数，第二季为其一半；活动种子使用配置中的权重；土地只影响最早可收菜时间。
- 种子品类、经验权重和土地增益统一定义在 `src/config.ts`，两个视图共用。

页面使用 Vue 3、Vite、TypeScript 和 Naive UI。计算在浏览器内完成，输入不会上传或持久保存。选择“此刻”时按当前分钟记录播种时间。

日期选择器的面板使用设备本地时区。在实行夏令时的地区，切换当天个别本地不存在的时间可能无法在面板中选取；已选时间的收获计算始终按北京时间解释。

## GitHub Pages 部署

网站地址：<https://longshihui.github.io/qq-farmer/>。

仓库的 **Settings → Pages → Build and deployment → Source** 设为 **GitHub Actions**。推送到 `main` 后，工作流会运行测试、以 `/qq-farmer/` 为资源基路径构建，并部署 `dist`。也可以在 **Actions → Deploy GitHub Pages → Run workflow** 手动部署。
